# quick-note — 빠른 기록

## 언제 쓰나
나중에 쓸 정보를 던질 때. "방금 A업체가 단가 조정 요청함", "메모: …", "이거 적어둬".
머리를 비우게 하는 가장 일상적인 기능.

## 저장 규약 (기준: `notes/README.md`)
**폴더는 고정 목록이 아니다.** `ls notes/` 로 **지금 실제로 있는 폴더**를 보고 그중에서 고른다.
설치 직후엔 `inbox/` 와 `issues/` 둘뿐이고, 나머지는 사용자가 자기 일에 맞게 만든다(`고객사/`·`영상/`·`자격증/` 등).
기준 문서는 `notes/README.md` 이고 `recall`·`import-sort` 가 **똑같이 이 규약을 따른다**.

기본 두 폴더의 뜻:

| 폴더 | 넣는 것 |
|---|---|
| `notes/inbox/` | 분류 애매한 것 **전부**. 마땅한 폴더가 없으면 여기 |
| `notes/issues/` | 아직 안 끝난 문제. **아침 브리핑이 이 폴더를 본다** (기능이 걸린 유일한 폴더) |

파일 경로 표기: `notes/<폴더>/YYYY-MM-DD-짧은제목.md`
(예: `notes/고객사/2026-07-20-A업체-단가조정.md` — 폴더 이름은 그 사람이 만든 것)

## 동작 순서
1. **분류 판단** — `ls notes/` 로 **있는 폴더**를 보고 그중 하나 선택. 마땅한 게 없으면 `inbox/`.
   **폴더를 마음대로 새로 만들지 않는다.** 필요해 보이면 저장은 `inbox/` 에 하고 **제안만** 한다 —
   "'영상' 관련이 8건 됐어요. `영상/` 으로 따로 뺄까요?" 승낙을 받으면 그때 만들고 옮긴다.
   **경계 규칙:** 특정 상대가 주인공이면 — 첫 문의·상담 통화라도 — 그 상대를 담는 폴더가 우선이다
   (상대 축으로 쌓여야 "그 사람 얘기"로 찾힌다). 아직 안 끝난 문제는 `issues/`. (기준: `notes/README.md`)
2. **파일 결정 — 저장 전 중복 검색(의무)** — 먼저 해당 폴더에서 같은 주제의 기존 파일을 찾는다
   (제목·태그·핵심어 기준). **날짜가 달라도 같은 주제면 새 파일을 만들지 말고 기존 파일에
   "## 추가 (YYYY-MM-DD)" 섹션으로 이어 적는다** (파일명 날짜는 최초 기록일 유지). 기존 파일이
   없을 때만 `notes/<폴더>/YYYY-MM-DD-짧은제목.md` 로 새로 만든다. 같은 주제 메모가 파일 여러 개로
   흩어지면 회상이 반쪽이 된다 — 이 검색은 생략하지 않는다.
3. **저장** — 아래 형식으로 기록. 던진 원문을 보존하고 한 줄 요약을 붙인다.
4. **짧게 확인 응답** — 어디에 저장했는지 1줄.
5. **상태 갱신** — `state/status.json` 의 `today.counts.notes` +1, `today.activities` 에
   `{time,type:"note",summary}` 추가, `updatedAt`·`lastActiveAt` 갱신 후 `state/dashboard-data.js`
   재생성 (`docs/STATE_CONTRACT.md` 준수).

## 저장 파일 형식
```markdown
# A업체 단가조정

- 날짜: 2026-07-20 14:30
- 분류: customers
- 태그: A업체, 단가

방금 미팅에서 A업체가 단가 조정 요청함. (원문)
요약: A업체 단가 재협의 필요 — 다음 미팅 전 견적 근거 준비.
```

## 응답 예시 (텔레그램)
```
기록했어요 → notes/고객사/2026-07-20-A업체-단가조정.md
(고객 기록으로 분류. '지난 A업체 얘기' 물어보면 찾아드릴게요.)
```
