# daily-briefing — 일정 브리핑 + 미팅 준비 + 일정 조율

## 언제 쓰나
"내일 일정 브리핑해줘", "오늘 뭐 있어?", "이번 주 미리 보자", "3시 미팅 준비 챙겨줘" 등
일정·미팅 준비 요청. 매일 아침 1분 브리핑이 대표적 장면.

**reminder 와의 경계:** "지금 브리핑·준비해줘"(즉시 정리) → 이 스킬. "○○ 전에/○요일에
알려줘·챙겨줘"(나중 시점의 알림 등록) → `reminder` 스킬. 등록된 리마인더를 브리핑에
표면화하는 것은 이 스킬의 몫이다.

## 동작 순서
1. **대상 기간 파악** — 오늘 / 내일 / 이번 주 / 특정 미팅.
2. **일정 읽기 (폴백 규약 — 순서 고정):**
   - ① **구글 캘린더 실연동** — `state/google-calendar.json` 이 있으면 이렇게 읽는다:

     ```bash
     bun tools/calendar-read.mjs --days 2      # 오늘·내일 (이번 주면 --days 7)
     ```

     종료 코드로 갈래가 갈린다: **0** 정상 · **2** 연결 안 됨(→ ②로) · **3** 연결은 됐는데
     못 읽음(→ **폴백으로 가되 사실대로 밝힌다**). 3번일 때 "일정 없음"이라고 말하지 않는다.
   - ② 없거나 실패하면 **ICS 비밀 주소**(`state/calendar.json`)를 읽는다.
   - ③ 그것도 없으면 **`notes/calendar-fallback.md`** 를 읽는다.
   - 이 순서와 규약(켜 둔 캘린더만·로컬 시각 변환)은 브리지의 `/api/calendar` 와 **같다** —
     브리핑과 대시보드가 같은 일정을 본다. 둘이 갈라지면 화면과 브리핑이 다른 말을 하게 되므로
     `tools/calendar-read.mjs` 와 `dashboard-server.py` 는 **함께** 고친다.

   - 이 순서는 `docs/SETUP_CALENDAR.md` 와 동일하다. 어느 경로든 결과 형식은 같다.

   > **①(실연동)이면 읽기만 하는 게 아니라 고칠 수도 있다** — "3시 미팅 4시로 옮겨줘" 같은
   > 조율 요청은 아래 **「일정 조율」** 절을 따른다. ②·③ 폴백에서는 못 고친다.
3. **미팅 준비 보강** — 각 일정의 상대(고객·업체)명으로 `notes/` 를 훑어(=recall 규약) 관련 기록을
   찾고, "챙길 것 / 지난 맥락"을 1~2줄로 붙인다. 관련 기록이 없으면 생략한다.
4. **열린 항목 표면화 (의무 — 생략 금지)** — 브리핑할 때마다 반드시 함께 짚는다. **읽기 순서:**
   - **① 기본: `state/status.json` 의 `todos[]` 를 읽는다** (reminder·issue-tracker 가 채워 둔 열린
     항목의 단일 소스). `state` 가 `open`/`overdue` 인 것만 대상:
     - `kind:"issue"` → "🔴 미해결" 줄로 표면화.
     - `kind:"reminder"` → `due` 가 지났거나(overdue) 임박한 것을 "⏰ 챙길 것" 줄로 표면화.
     - `state:"done"` 은 제외. `due` 와 오늘을 비교해 지난 것을 먼저 보여준다.
   - **② 이슈 폴더 대사(의무 — todos가 있어도 항상)** — `notes/issues/` 에서 상태가 "열림/진행"인
     파일 중 `source` 경로가 todos에 **없는** 것을 찾는다. 발견하면 ① 이번 브리핑에 함께 표면화하고
     ② **`todos[]` 에 `open` 으로 등록**해 다음부터는 단일 소스에 잡히게 한다(자가 치유).
     todos 도입 전 데이터·수동으로 만든 이슈가 조용히 새는 것을 막는 장치다 — 실주행에서
     "todos만 믿다가 옛 열린 이슈를 놓친" 사례가 실제 관찰되어 의무화한다.
   - ③ `todos[]` 필드 자체가 없으면(아주 옛 데이터) `notes/inbox/` 리마인더까지 폴더 스캔으로 보완한다.
   해당 항목이 없을 때만 생략한다. (일정만 보여주고 열린 이슈를 놓치는 것이 이 기능의 대표 실패 사례다.)
5. **간결 브리핑 출력** (아래 형식). 텔레그램 화면에 맞게 짧게.
6. **상태 갱신** — `state/status.json` 의 `today.counts.briefings` +1, `today.activities` 에
   `{time,type:"briefing",summary}` 추가, `session.lastActiveAt`·`updatedAt` 갱신 후
   **`./refresh-dashboard.sh` 실행**으로 `state/dashboard-data.js` 재생성 (`docs/STATE_CONTRACT.md` 준수).

## 일정 조율 — 만들기 · 고치기 · 지우기 · 되돌리기

"금요일 2시에 A업체 미팅 잡아줘", "내일 3시 미팅 4시로 옮겨줘", "그 일정 취소해줘" 처럼
**일정을 바꿔 달라는 요청**은 `tools/calendar-write.mjs` 로 직접 처리한다.
**구글 캘린더 실연동(위 ①)일 때만 된다.**

```bash
bun tools/calendar-read.mjs --json                     # ① 먼저 대상 일정의 id 를 확인한다
bun tools/calendar-write.mjs create --title "A업체 미팅" --start "2026-08-14T14:00" --end "2026-08-14T15:00"
bun tools/calendar-write.mjs create --title "워크숍" --start "2026-08-14" --all-day
bun tools/calendar-write.mjs update --id <일정id> --start "2026-08-14T16:00" --end "2026-08-14T17:00"
bun tools/calendar-write.mjs delete --id <일정id>        # 되돌리기용 원본을 함께 알려준다
bun tools/calendar-write.mjs undo   --json '<delete 가 알려준 JSON 그대로>'
```

규율:

- **고치거나 지우기 전에 어느 일정인지 확정한다.** `--json` 으로 id 를 확인하고 후보가 둘 이상이면
  **묻는다.** 짐작으로 남의 일정을 지우지 않는다.
- **고치기·지우기는 실행 전에 한 번 확인받는다** — *"8/14 14:00 A업체 미팅을 16:00 으로 옮길게요, 맞나요?"*
  새로 만드는 건 내용이 분명하면 바로 해도 된다.
- **종일 일정의 끝 날짜는 사람 말 그대로 준다** — "8/10 하루"면 `--start 2026-08-10 --all-day`(`--end` 생략),
  "8/10~8/12 사흘"이면 `--end 2026-08-12`. 구글 규약(배타적 end)으로 넓히는 건 **도구가 한다** —
  여기서 하루를 더하지 않는다.
- **지운 뒤에는 되돌릴 수 있다는 것을 함께 알린다** — *"되돌릴까요?"* 도구가 알려준 `undo` 명령을
  그대로 실행하면 된다. **그 JSON 의 날짜를 손보지 않는다**(구글 원본이라 만지면 하루가 어긋난다).
- **종료 코드 4 = 읽기 전용 캘린더**(공휴일·공유받은 것). 구글이 막은 것이지 우리 문제가 아니다.
  *"그 캘린더는 읽기 전용이라 제가 못 고쳐요"* 라고 그대로 전한다. **다른 캘린더에 몰래 만들지 않는다.**
  (2 = 미연결 · 3 = 연결 끊김 · 5 = 구글이 거절)
- **폴백(②·③)에서는 못 한다.** 사실대로 말한다 — *"지금 연결로는 제가 일정을 바꾸지는 못해요.
  `notes/calendar-fallback.md` 에는 적어 둘게요."* 없는 기능을 있다고 하지 않는다.
- 일정을 바꿨으면 `state/status.json` 갱신 + `./refresh-dashboard.sh` 는 다른 업무와 똑같이 한다.

## 읽는 위치
- 캘린더 연동 결과 **또는** `notes/calendar-fallback.md`
- 미팅 상대 관련 기록: `notes/` **전체를 훑는다** — 폴더 이름은 사람마다 다르다(`고객사/`·`회의/`·`영상/`). 있는 폴더 중에서 찾는다

## 출력 형식 예시
```
[내일(7/21) 브리핑]
• 10:00 A업체 미팅 — 단가 재협의
  ↳ 지난주 A업체가 단가 조정 요청함(기록 있음). 견적 근거 챙기세요.
• 15:00 B고객 코칭
• 저녁 일정 없음

🔴 미해결: 반품 클레임 1건 (7/19, 열림) — 오늘 회신 방침 정하면 좋겠어요.
⏰ 챙길 것: 10:00 미팅 전 '견적서 확인' 리마인더.
```
일정이 하나도 없으면: "내일은 등록된 일정이 없어요. 캘린더를 연결했는지, 또는
`notes/calendar-fallback.md` 에 일정을 넣었는지 확인해 주세요."
