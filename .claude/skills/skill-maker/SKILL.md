# skill-maker — 새 스킬 만들기

## 언제 쓰나

**이 파트너는 완성품이 아니라 뼈대다.** 기본 업무 일곱 가지 밖의 일이 반복되기 시작하면
그때 하나씩 붙이면 된다. 그 붙이는 일을 이 스킬이 한다.

- "매주 유튜브 본 것 정리하는 거 스킬로 만들어줘"
- "납품처별 단가표 갱신하는 거 매번 하는데 자동으로 못 해?"
- "이력서에서 자격증만 뽑아내는 기능 만들어줘"

**반대로, 만들지 말아야 할 때가 있다.** 아래는 만들기 전에 말한다:
- **한 번만 할 일** — 스킬은 반복되는 것에만 값이 있다. 그냥 지금 해 주면 된다
- **기본 업무와 겹치는 것** — `quick-note`·`recall`·`daily-briefing`·`draft-writer`·
  `issue-tracker`·`reminder`·`import-sort` 가 이미 하는 일이면 그 스킬을 쓰면 된다
- **이 파트너가 못 하는 것** — 메일·카톡 **자동 발송**, 외부 서비스 로그인이 필요한 일,
  이 폴더 밖의 파일 조작. 스킬을 만들어도 안 된다. **된다고 적지 않는다.**

---

## 1. 물어본다 (한 번에 하나씩)

받아쓰기가 아니라 **인터뷰다.** 답이 뭉뚱그려지면 되묻는다.

1. **"그 일을 마지막으로 했을 때, 뭘 어떻게 하셨어요?"**
   → 단계를 사람 말로 받는다. "정리한다" 같은 말이 나오면 *"정리하면 결과물이 뭐가 되나요?"* 로 판다.
2. **"언제 이걸 부르고 싶으세요? 실제로 하실 법한 말로요."**
   → 트리거 문장 2~3개. **그 사람이 쓸 말**이어야 한다. 내가 지어내지 않는다.
3. **"결과가 어디에 남아야 하나요?"**
   → `notes/` 의 어느 폴더인지 · 화면에 떠야 하는지 · 그냥 답만 보면 되는지.
4. **"뭘 보고 하나요?"**
   → 기존 기록 · `_import/` 의 파일 · 캘린더 · 아무것도 안 봐도 되는지.

받은 답을 **한 줄로 되비추고 확인받는다.**
> "**'유튜브 정리'** — 매주 일요일에 본 영상 목록을 던지면, 주제별로 묶어서
> `notes/영상/` 에 한 건으로 남긴다. 맞나요?"

---

## 2. 이름을 정한다

- 폴더 이름은 **영문 소문자 + 하이픈** (`youtube-digest`, `price-sheet`). 파일 경로가 되기 때문이다.
- 사람에게 보이는 이름은 **한국어**로 `description` 안에 넣는다.
- 기존 스킬과 겹치지 않는지 `ls .claude/skills/` 로 확인한다.

---

## 3. 파일을 만든다

`.claude/skills/<이름>/SKILL.md` **한 장**이면 된다. 뼈대는 이렇다:

```markdown
---
name: <폴더와 같은 이름>
description: "<한국어 한 줄 설명>. '<트리거1>', '<트리거2>', '<트리거3>' 처럼 <어떤 상황>일 때 사용한다. <무엇을 해서 어디에 남기는지>."
---

# <이름> — <한국어 이름>

## 언제 쓰나
<어떤 상황에서 부르는지. 실제로 할 법한 말 2~3개>

## 동작 순서
1. <먼저 무엇을 읽는지 — 없으면 "읽을 것 없음">
2. <무엇을 판단·가공하는지>
3. <어디에 어떤 형식으로 남기는지 — 경로를 정확히>
4. <짧게 확인 응답>
5. <상태 갱신이 필요하면: state/status.json 갱신 + ./refresh-dashboard.sh>

## 남기는 형식
<실제 예시 한 덩어리>

## 하지 않는 것
<이 스킬이 넘지 말아야 할 선. 추측으로 채우지 않기 등>
```

**`description` 이 제일 중요하다.** 파트너는 이 줄을 보고 언제 이 스킬을 쓸지 정한다.
트리거 문장이 빠지면 **만들어도 발동하지 않는다.**

### 기존 규약을 어기지 않는다

- `notes/` 에 남긴다면 **`notes/README.md` 가 기준**이다. 폴더를 마음대로 새로 만들지 않는다 —
  필요하면 `inbox/` 에 넣고 제안만 한다.
- 파일명은 `YYYY-MM-DD-짧은제목.md`.
- 상태 파일은 `docs/STATE_CONTRACT.md` 를 따른다. **`state/team.json` 은 건드리지 않는다**
  (그건 `project-team` 것이다).

---

### 파일을 쓸 때 **승인 창이 뜬다 — 이건 정상이다**

`.claude/` 는 이 파트너의 **설정이 사는 곳**이라, Claude Code 가 권한 목록과 **무관하게** 보호한다
(실측: `Edit(./**)` 로도, `Edit(./.claude/skills/**)` 를 따로 넣어도 안 열린다. `Write(...)` 규칙은
파일 검사에 아예 매칭되지 않는다). 그래서 스킬 파일을 쓸 때는 **반드시 승인 창이 뜬다.**

**그게 맞다.** 새 스킬은 곧 "앞으로 이렇게 행동해라"는 지시다 — 사람이 한 번 보고 허락해야 한다.
그러니 미리 알린다:

> "파일을 만들 건데 **승인 창이 하나 뜰 거예요.** 새 기능을 붙이는 일이라 한 번 확인을 받습니다.
>  내용은 이거예요 — (요약) — 괜찮으시면 허용을 눌러 주세요."

**승인 전에 무엇을 만들지 요약해서 먼저 보여 준다.** 창만 던져 놓고 기다리지 않는다.

---

## 4. 새 명령이 필요하면 **권한에 함께 넣는다** (빠뜨리기 쉬운 곳)

스킬이 지시하는 명령이 `.claude/settings.json` 의 `permissions.allow` 에 없으면,
쓸 때마다 **권한을 묻는 창에 막힌다.** 스킬만 만들고 여기를 빠뜨리는 일이 실제로 반복됐다.

```jsonc
// .claude/settings.json
"permissions": {
  "allow": [
    "Bash(./refresh-dashboard.sh)",
    "Edit(./notes/**)"        // ← 새 스킬이 쓰는 경로·명령을 여기 추가
  ]
}
```

- 파일을 쓰는 규칙은 **`Write(경로)` 가 아니라 `Edit(경로)`** 로 적는다
  (`Write` 규칙은 파일 권한 검사에 매칭되지 않는다 — 실측).
- 새 명령을 쓰지 않고 기존 도구만 쓰면 **손댈 필요 없다.** 그때는 건너뛴다.

---

## 5. 그 자리에서 시험한다 (여기까지가 만들기다)

파일만 만들고 끝내지 않는다.

1. **새 스킬은 다음 세션부터 인식된다.** 그러니 이렇게 안내한다 —
   *"터미널에서 `claude` 를 한 번 껐다 켜 주세요. 그다음에 '<트리거 문장>' 이라고 해 보시면 돼요."*
2. 재시작 뒤 **트리거 문장을 실제로 넣어 보게 하고**, 결과 파일이 진짜 생겼는지 같이 확인한다.
3. 안 되면 대개 **`description` 의 트리거 문장이 실제로 쓸 말과 다르다.** 그 줄부터 고친다.

---

## 6. 마지막 보고

```
'유튜브 정리' 스킬을 만들었어요.

  파일   .claude/skills/youtube-digest/SKILL.md
  부르는 말  "이번 주 유튜브 정리해줘"
  하는 일  던진 목록을 주제별로 묶어 notes/영상/ 에 한 건으로 남겨요
  권한   따로 추가한 건 없어요 (기존 기록 폴더만 씁니다)

터미널에서 claude 를 한 번 껐다 켜신 다음, "이번 주 유튜브 정리해줘" 라고 해 보세요.
```

## 하지 않는 것

- **없는 기능을 있다고 적지 않는다.** 발송·외부 로그인·폴더 밖 접근은 스킬로도 안 된다.
- **사용자의 대답을 대신 지어내지 않는다.** 물었으면 답을 기다린다.
- 한 번에 여러 스킬을 만들지 않는다. 하나 만들고 **써 보게 한 뒤** 다음 것으로 간다.
