# import-sort — 예전 기록 들여오기

## 언제 쓰나

다른 곳(카톡·노션·메모앱·엑셀·워드)에 있던 기록을 이 파트너가 쓸 수 있게 옮길 때. 셋업 단계 4가 이 스킬로 위임한다. 나중에 추가로 옮길 때도 같은 방식이다.

**이 스킬이 없으면 `notes/` 가 빈 채로 시작하고, 회상·이슈 묶기·맥락 있는 초안이 전부 범용 답이 된다.** 그래서 이 단계가 파트너 성능을 가장 크게 좌우한다.

---

## 절대 규칙 4가지

1. **원본을 지우지 않는다.** `_import/` 는 그대로 둔다. 정리가 틀렸을 때 돌아갈 곳이다.
2. **지어내지 않는다.** 원본에 없는 날짜·금액·이름·결론을 채우지 않는다. 애매하면 `(원본에 없음)` 이라고 적는다. **지어낸 기록은 빈 기록보다 나쁘다** — 이후 모든 회상을 오염시킨다.
3. **출처를 반드시 남긴다.** 모든 결과 파일에 어느 원본에서 왔는지 경로를 적는다. 그래야 나중에 "이거 틀렸는데" 를 잡을 수 있다.
4. **`_import/` 는 회상 대상이 아니다.** 원본은 검색되지 않는다. `recall` 이 읽는 건 `notes/` 뿐이다. (원본과 정리본이 둘 다 걸리면 같은 사실이 두 번 나온다.)

---

## 동작 순서

### 1. 훑어보기 — 무엇이 들어왔나

`_import/` 를 나열하고(`ls -la _import`), 각 파일의 **형식·크기·대략의 기간**을 파악한다. 비어 있으면 "아직 비어 있어요" 하고 멈춘다.

먼저 **한 줄로 보고**한다: "텍스트 3개, CSV 1개, PDF 1개 들어왔네요. 카톡 대화 같은 게 하나 보이고요."

### 2. 크면 자른다 — 통째로 삼키지 않는다

카톡 몇 년치처럼 큰 파일은 한 번에 다 읽을 수 없다. **다 읽은 척하지 않는다.**

- 앞뒤를 먼저 읽어 **어떤 기간·어떤 상대**인지 파악한다
- **최근 것부터** 처리한다. 오래된 것일수록 지금 덜 쓰인다
- 다 못 하면 **어디까지 했는지 말한다**: "최근 3개월치(약 40건)를 정리했어요. 그 앞은 아직 원본 그대로 있고, 원하시면 이어서 할게요."

**한 번에 다 끝내는 것보다 어디까지 했는지 정확히 아는 게 낫다.**

### 3. 쪼갠다 — 한 파일 안에 여러 기록이 섞여 있다

카톡 대화 하나에 벤더 얘기·클레임·일정이 다 섞여 있다. **파일 하나 = 기록 하나가 아니다.**

의미 단위로 쪼갠다:
- **상대가 바뀌면** 다른 기록
- **주제가 바뀌면** 다른 기록
- **날짜가 크게 떨어지면** 다른 기록

잡담·인사·"넵"만 있는 구간은 **버린다.** 전부 옮기는 게 목적이 아니라 **나중에 찾을 것**을 옮기는 게 목적이다.

### 4. 분류한다 — **있는 폴더 중에서** (기준: `notes/README.md`)

**폴더는 고정 목록이 아니다.** 먼저 `ls notes/` 로 지금 있는 폴더를 본다. 설치 직후엔 `inbox/` 와
`issues/` 둘뿐이고, 나머지는 사용자가 자기 일에 맞게 만든 것이다(`고객사/`·`영상/`·`자격증/`).

| | 규칙 |
|---|---|
| **있는 폴더에 맞으면** | 거기 넣는다. 특정 상대가 주인공이면 그 상대를 담는 폴더가 우선이다 — 상대 축으로 쌓여야 "그 사람 얘기"로 찾힌다 |
| **아직 안 끝난 문제** | `issues/` — 아침 브리핑이 이 폴더를 보므로 여기 있어야 놓치지 않는다 |
| **마땅한 게 없으면** | `inbox/`. **주저하지 말 것** |

**폴더를 마음대로 만들지 않는다.** 다만 이관은 한 번에 여러 건이 들어오므로 **덩어리가 보이면
제안한다** — 넣기는 `inbox/` 에 하고, 보고할 때 이렇게 적는다:

> `inbox/` 에 넣은 것 중 **영상 관련이 6건**이에요. `영상/` 폴더로 따로 뺄까요?
> (원하시면 "영상 폴더 만들어줘" 라고만 하시면 옮겨 둘게요.)

승낙을 받으면 그때 폴더를 만들고 옮긴다. **묻지 않고 만들지 않는다** — 폴더 이름은 그 사람의
말이어야 하고, 내가 지어낸 이름은 나중에 안 쓰인다.

### 5. 파일명 — **원본이 기록된 날짜**를 쓴다

```
notes/<폴더>/YYYY-MM-DD-짧은제목.md
```

날짜는 **그 일이 기록된 날**이다. 오늘이 아니다. 우선순위:

1. **원본 본문에 적힌 날짜** (카톡 타임스탬프, 문서 안의 날짜) ← 가장 정확
2. 없으면 **원본 파일의 수정일**
3. 그것도 없으면 **오늘 날짜**를 쓰고, 본문에 `(원본에 날짜 없음 — 들여온 날로 적음)` 이라고 밝힌다

> **이게 왜 중요한가**: "지난달 그 건" 이라고 물었을 때 파일명 날짜로 기간을 좁힌다. 3월 일을 오늘 날짜로 넣으면 **넣을수록 회상이 나빠진다.**

### 6. 파일 안 형식

```markdown
# 짧은제목

- 날짜: 2026-03-14
- 분류: 고객사
- 태그: A업체, 단가
- 원본: _import/kakao-A업체.txt
- 들여온 날: 2026-08-01

## 요약

(무슨 일이었는지 2~4줄. 원본에 있는 사실만.)

## 원문

> (근거가 되는 원문을 짧게 인용. 길면 핵심 부분만.)
```

**`원본`·`들여온 날` 두 줄을 빠뜨리지 않는다.** 나중에 "이거 어디서 나온 거지"를 답할 수 있어야 한다.

### 6-2. 글이 아닌 원본 — 표·PDF·이미지

**먼저 열어본다.** 읽어보지도 않고 "못 옮긴다"고 하지 않는다.

| 형식 | 어떻게 |
|---|---|
| **`.csv` · `.xlsx`** | `notes/` 가 **받는 형식**이다(화면이 표로 그려 준다). `cp` 로 **파일 자체를 옮기고** 파일명은 §5 규칙(원본 날짜)을 그대로 쓴다. **그리고 무슨 표인지 요약 노트를 한 건 따로** 만든다 — 표 자체는 검색에 잘 안 걸려서, 요약이 있어야 "매출 어땠지?"로 찾힌다 |
| **`.pdf`** | **읽어서** 요약 노트를 만든다. `notes/` 는 pdf 를 화면에 안 띄우므로 **원본은 `_import/` 에 두고 요약만** 넣되, `원본:` 줄에 경로를 적어 되짚을 수 있게 한다 |
| **이미지** | 마찬가지로 읽어서 요약. 화이트보드 사진·영수증도 대개 읽힌다 |

읽었는데 **정말 내용을 알 수 없으면**(글자가 뭉개진 스캔, 깨진 파일) 그때 **"못 읽었다"고 말한다.**
추측해서 채우지 않는다 — 그건 절대 규칙 2번 위반이다.

### 7. 이어 적기 — 이미 있는 기록과 겹칠 때

같은 상대·같은 날짜의 기록이 이미 있으면 **새 파일을 만들지 말고 그 파일에 이어 적는다.** 같은 사실이 두 파일에 흩어지면 회상이 반쪽만 찾는다.

### 8. 보고한다 — 창작 없이, 숫자 그대로

끝나면 **무엇이 어디로 갔는지** 보여준다:

```
들여왔어요 — 원본 4개 → 기록 23건

  고객사/   14건   (A업체 8 · B벤더 6)
  issues/    3건
  미팅/      4건
  inbox/     2건
  표 1건     매출표.csv → 고객사/2026-01-매출표.csv (화면에서 표로 보여요)

  기간: 2026-03-14 ~ 2026-07-28
  원본은 _import/ 에 그대로 있어요.

⚠ 처리 못 한 것
  · kakao-전체.txt 의 2026-03 이전 구간 (약 1,200줄) — 이어서 할까요?
  · 스캔본.jpg — 글자가 흐려서 못 읽었어요. 다시 찍어 주시면 처리할게요.
```

**못 한 것을 반드시 적는다.** 숫자를 부풀리지 않는다. 23건이면 23건이다.

### 9. 바로 한 번 꺼내 보게 한다 ⭐

정리했다고 끝이 아니다. **돌아오는 걸 한 번 겪어야** 이 도구를 믿게 된다.

> "지금 바로 써 볼게요. 아까 '찾기 어려웠다'고 하신 그거, 저한테 물어보세요."

`recall` 로 실제로 찾아 보여준다. **못 찾으면 정직하게 말하고** 어떤 표현으로 물으면 되는지 같이 찾는다. 못 찾은 걸 찾은 척하지 않는다.

### 10. 상태 갱신

`state/status.json` 의 `today.activities` 에 `{time, type:"note", summary:"기록 들여옴: 원본 N개 → M건"}` 추가, `today.counts.notes` 를 **실제 만든 건수만큼** 올리고, `lastActiveAt`·`updatedAt` 갱신 후 `./refresh-dashboard.sh` 를 실행한다. (`docs/STATE_CONTRACT.md` 준수)

## 자주 만나는 원본별 요령

| 원본 | 특징 | 요령 |
|---|---|---|
| **카톡 내보내기** | `2026. 3. 14. 오후 2:31, 이름 : 내용` 형식. 잡담이 대부분 | 타임스탬프로 날짜를 얻는다. 상대별·주제별로 쪼갠다. 잡담은 버린다 |
| **노션 Markdown** | 이미 제목·구조가 있음 | 구조를 살려 그대로 옮긴다. 페이지 하나가 기록 하나인 경우가 많다 |
| **메모앱·워드** | 날짜가 없는 경우가 많다 | 파일 수정일을 쓰고 본문에 밝힌다 |
| **엑셀·CSV** | **화면이 표로 그려 준다** | `.csv`·`.xlsx` 는 `notes/` 가 받는 정식 형식이다. **파일을 그대로 복사**하고(§5 날짜 규칙 그대로) **무슨 표인지 요약 노트를 한 건 같이** 만든다 — 표 자체는 검색에 잘 안 걸리므로 요약이 있어야 회상된다 |
| **PDF** | **읽을 수 있다** (한글 포함) | 계약서·회의록·명세서는 회상 재료로 값지다. **읽어서 요약 노트를 만들고** 원본 경로를 적는다. 단 `notes/` 는 pdf 를 화면에 안 띄우므로 **원본은 `_import/` 에 두고 요약만 `notes/` 로** |
| **이미지·스캔** | 대개 읽을 수 있다 | 화이트보드 사진·영수증도 읽어서 요약한다. **글자가 안 보이면 그때 못 읽는다고 말한다** — 미리 포기하지 않는다 |

## 하지 않는 것

- 원본 삭제
- `_import/` 밖의 파일을 읽거나 옮기기
- 원본에 없는 내용 보충
- 처리 못 한 것을 조용히 넘기기
- "다 정리했어요" 라고 말하면서 실제로는 일부만 한 것
- **읽어보지도 않고 "이건 못 옮겨요" 라고 하기** — PDF·엑셀·이미지는 대개 읽힌다. **열어보고 나서** 판단한다
