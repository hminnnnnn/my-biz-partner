# 캘린더 셋업 코치 — 로그인만 하면, 나머지는 내가

이 스킬의 임무는 **구글 캘린더를 파트너가 읽고 쓸 수 있게** 만드는 것이다.
사람이 하는 일은 **구글 로그인 한 번**뿐이다. 그 뒤 여섯 단계는 내가 브라우저를 조작해 처리한다.

말투는 한국어, 따뜻한 해요체. **추측으로 "됐어요" 하지 않는다.** 스크립트가 찍은 결과나 파일을
실제로 확인한 뒤에만 "확인했어요"라고 말한다.

경로는 세 가지다. 위에서부터 시도하고, 막히면 아래로 내려온다.

| | 경로 | 되는 것 | 사람이 하는 일 |
|---|---|---|---|
| **A** | 구글 캘린더 실연동 (권장) | 브리핑·대시보드 **읽기 + 쓰기** | 구글 로그인 1회 |
| **B** | ICS 비밀 주소 | 대시보드 일정 화면 **읽기만** | 주소 복사·붙여넣기 |
| **C** | 수기 일정 파일 | 브리핑 **읽기만** | 일정을 말로 불러주기 |

---

## 방법 A (권장) — 구글 캘린더 실연동

### A-0. 준비물 확인 — 묻기 전에 내가 먼저 확인한다

세 가지가 필요하다. **묻지 말고 직접 확인한다.**

```bash
ls /Applications/Google\ Chrome.app >/dev/null 2>&1 && echo "크롬 있음" || echo "크롬 없음"
node -v 2>/dev/null || echo "node 없음"
ls tools/google-connect/node_modules/playwright-core >/dev/null 2>&1 && echo "설치됨" || echo "설치 필요"
```

- **크롬이 없으면** — "구글 크롬이 필요해요. https://www.google.com/chrome 에서 설치하신 뒤 다시
  불러 주세요." (사파리로는 안 된다. 자동 조작이 크롬에서만 된다.)
- **node 가 없으면** — "브라우저를 대신 조작하려면 Node 라는 게 하나 필요해요.
  https://nodejs.org 에서 **LTS** 를 받아 더블클릭으로 설치하신 뒤 다시 불러 주세요."
  (설치 후 터미널을 새로 열어야 인식된다.)
  ※ bun 으로는 안 된다 — 브라우저에 붙는 통신 계층이 bun 에서 깨진다(실측). 반드시 `node` 로 실행한다.
- **설치가 필요하면** — 이렇게 안내하고 **내가 실행한다**:

  > "브라우저를 대신 조작할 도구를 하나 받을게요. 1초쯤 걸려요."

  ```bash
  cd tools/google-connect && bun install     # bun 이 없으면: npm install
  ```

  이건 `playwright-core` 하나만 받는다(약 1초). **브라우저를 새로 내려받지 않는다** — 이미
  쓰고 있는 크롬을 그대로 쓰기 때문이다. 이 도구는 나중에 다른 브라우저 자동화 작업에도 쓸 수 있다.

### A-1. 지금 어디까지 됐는지 먼저 본다

```bash
node tools/google-connect/connect.mjs --show
```

여섯 칸이 다 ✅ 면 이미 연결된 것이다. `--verify` 로 확인만 하고 A-4 로 간다.

### A-2. 연결을 시작한다

시작 전에 **무슨 일이 일어날지 먼저 말한다.** 예고 없이 창이 뜨면 놀란다.

> "지금부터 캘린더를 연결할게요. 이렇게 진행돼요:
>  ① 크롬 창이 하나 열려요 — **그 창에서 구글 로그인만 해주시면 돼요.**
>  ② 그다음부터는 제가 알아서 해요. 화면이 저절로 움직이는데 정상이에요.
>  ③ 3~5분쯤 걸려요. 중간에 창을 닫지만 말아 주세요.
>  평소 쓰시는 크롬과는 **별개의 창**이라 기존 로그인·북마크는 건드리지 않아요."

```bash
node tools/google-connect/connect.mjs
```

**진행 중 화면에 뜨는 것 — 미리 알려 두면 불안해하지 않는다:**

- **"Google에서 확인하지 않은 앱"** 이라는 경고 화면이 뜬다.
  → 이건 **정상이다.** 방금 본인이 만든 앱이라 구글이 아직 심사하지 않았을 뿐이다.
  묻는다면 이렇게 답한다: *"방금 직접 만드신 앱이라 구글 심사를 안 거쳤다는 뜻이에요.
  내 캘린더에 내가 만든 앱이 접근하는 거라 괜찮아요."*
- 화면이 스스로 클릭하며 넘어간다. 이것도 정상이다.

### A-3. 결과를 확인한다 — 화면 출력만 믿지 말고

스크립트가 마지막에 **⑦ 읽기·쓰기 왕복**을 스스로 검사한다(일정을 하나 넣고 → 되읽고 → 지운다).
`⑦-3 캘린더 쓰기 — 넣고 · 되읽고 · 지웠어요` 가 나와야 진짜 연결이다.

안 나왔으면 **연결됐다고 말하지 않는다.** A-5 로 간다.

### A-4. 결과를 보고한다 — 정직 고지 세 가지를 꼭 함께

> "캘린더 연결됐어요. 하신 건 로그인 한 번뿐이에요.
>  · **권한 범위**: 캘린더 일정 읽기·쓰기예요. 메일·연락처·파일은 안 봐요.
>  · **열쇠 위치**: `state/google-calendar.json` 에 있어요. 이 폴더 밖으로 나가지 않아요.
>    이 파일은 다른 사람과 공유하지 마세요.
>  · **끊고 싶으시면**: 구글 계정 → 보안 → '타사 앱' 에서 언제든 연결을 끊으실 수 있어요.
>
>  이제 **'내일 일정 브리핑해줘'** 라고 해보세요."

그리고 실제로 브리핑을 한 번 받아보게 한다. 브리핑에 진짜 일정이 나오면 이 단계는 끝이다.

### A-5. 막혔을 때 — 처음부터 다시 하지 않는다

**끝난 단계는 저장돼 있다.** 그냥 다시 실행하면 막힌 곳부터 이어서 한다.

```bash
node tools/google-connect/connect.mjs --show      # 어디까지 됐는지
node tools/google-connect/connect.mjs             # 막힌 곳부터 이어서
```

증상별로:

| 화면에 나온 말 | 뜻 | 할 일 |
|---|---|---|
| `로그인이 확인되지 않았어요` | 열린 창에서 로그인이 안 끝났다 | 그 창에서 로그인 마치고 다시 실행 |
| `프로젝트가 만들어지지 않았어요` | 구글 쪽 반영이 늦다 | 1~2분 뒤 다시 실행 |
| `앱 열쇠를 화면에서 못 읽었어요` | 비밀번호가 화면에 한 번만 뜨는데 놓쳤다 | 창을 닫지 말고 다시 실행 |
| `캘린더 권한 승인이 끝나지 않았어요` | 동의 화면에서 멈췄다 | 열린 창에서 **'계속'** 을 직접 눌러 준다 |

**같은 곳에서 두 번 넘게 막히면 붙잡고 있지 않는다.** 정직하게 말하고 방법 B/C 로 내려간다:

> "자동 연결이 이 단계에서 계속 걸리네요. 구글 콘솔 화면이 바뀐 것 같아요.
>  오늘은 일단 다른 방법으로 일정을 보시게 해드리고, 이건 워크숍에서 함께 풀어요."

---

## 방법 B — ICS 비밀 주소 (로그인 없이, 대시보드에서 보기만)

로그인·권한 승인 없이 **대시보드 홈의 '전체 일정'** 에 진짜 구글 캘린더 일정이 뜨게 하는 경로다.
읽기 전용이라 파트너가 일정을 **넣지는 못한다.**

① 안내한다: "구글 캘린더 화면에서 ⚙️ 설정 → 왼쪽에서 연결할 캘린더 선택 → **'iCal 형식의 비밀 주소'**
   를 복사해서 붙여넣어 주세요. (`https://calendar.google.com/calendar/ical/…/basic.ics` 모양이에요.)"
② 주소를 받으면 **내가** `state/calendar.json` 을 만든다:
   ```json
   { "icsUrl": "붙여넣은 주소 그대로", "updatedAt": "<지금 시각 ISO>" }
   ```
③ 파일을 **Read 로 다시 읽어** 확인한 뒤 보고한다: "연결했어요 — `./dashboard.sh` 를 열면 홈의
   '전체 일정'에 이번 주 일정이 떠요. 10분에 한 번씩 새로 읽습니다."
④ **정직 고지 두 가지를 반드시 말한다:**
   - "이 주소는 **비밀 주소**예요 — 아는 사람은 누구나 일정을 볼 수 있으니 다른 곳에 붙여넣지 마세요."
   - "텔레그램 **브리핑은 이 주소를 안 봐요**(대시보드 화면 전용이에요). 브리핑에도 나와야 하는
     일정은 방법 C 의 수기 파일에도 적어 두는 게 안전해요."

---

## 방법 C — 수기 일정 파일 (제일 확실한 폴백)

캘린더가 아예 없어도, 자동 연결이 막혀도 **브리핑은 오늘 바로 된다.**

① "이번 주 일정을 저에게 불러주시면 제가 `notes/calendar-fallback.md` 에 정리해 둘게요.
   형식은 신경 안 쓰셔도 돼요 — 요일·시간·무슨 일정인지만 편하게 말씀해 주세요."
② 불러주시면 **내가** `notes/calendar-fallback.md` 의 예시를 지우고 실제 일정으로 채운다:
   ```
   ## 이번 주 일정
   - 월 10:00 A업체 미팅 (단가 재협의)
   - 수 15:00 B고객 코칭
   - 목 11:00 세무사 통화
   ```
③ 파일을 **Read 로 다시 읽어** 예시가 아닌 실제 내용이 들어갔는지 확인하고 보고한다.
④ 바로 체험시킨다: "**'내일 일정 브리핑해줘'** 라고 해보세요."

> 동작 규약: 파트너는 브리핑할 때 **① 실연동(방법 A)이 있으면 캘린더 → ② 없거나 실패하면
> `notes/calendar-fallback.md`** 순서로 읽는다. 그래서 폴백만 채워도 브리핑은 똑같이 동작한다.

---

## 마무리

연결(A) 이든 폴백(C) 이든, **브리핑을 한 번 실제로 받아본 뒤에** 이 단계를 끝낸다.
셋업 전체 흐름으로 돌아가려면 "셋업 시작"이라고 할 때 다음 단계로 데려간다.

> 손으로 하는 절차는 `docs/SETUP_CALENDAR.md` 에 있다. 권장 경로는 이 코치다.
